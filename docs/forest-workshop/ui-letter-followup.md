# Forest Workshop 0.8.1 — UI·편지 후속 작업 및 검증

기준: main `54fbd7f9c`(PR #26 병합 이후). 작업 브랜치 `work/forest-ui-letter-reliability`, PR #27. 검증일 2026-11-04.

## 사용 흐름 변경

- **생산 설정:** 품목 4개씩 화살표로 선택 → 목표 재고 직접 입력/± 조절 → 해당 물건 자동 생산. 기존 제작 트리 명령을 사용하고 성공하면 작업 현황으로 돌아간다. 요청 도중 다른 시설로 이동하거나 설정을 바꾸면 그 선택을 덮어쓰지 않는다. 390×844에서 자동 생산 버튼과 수동 설정 입구까지 스크롤 없이 보이는지 좌표로 검증했다.
- 수동 켜짐·목표 재고·작업 우선순위·추천 설정은 같은 생산 설정 탭의 **켜짐 · 목표 재고 · 작업 순서 직접 설정**에 유지한다. 자동 설정은 관련 재료도 준비하고 다른 품목은 쉬도록 기존 규칙을 적용한다. 잠긴 시설은 준비만 설정하며 자원 지급이나 해금은 하지 않는다.
- **주민:** 중복 이름과 중첩 카드를 줄이고 초상·상태·행동을 먼저 표시한다. 특기와 이름 편집은 펼쳐 확인한다. 팝업 CSS가 뒤쪽 공통 backdrop 규칙에 덮여 하단에 붙던 오류를 수정했다. 주민 상세·프로필·초대권 상점의 실제 중심 좌표를 검사한다.
- **무료 초대권 상점:** 기존 선물/초대권 그림, 지급량, 보유량과 수령 결과를 구분한다. 결과 공간을 미리 확보해 반복 수령 시 버튼 위치가 움직이지 않는다. 실제 결제나 일일 제한은 추가하지 않았다.

## 편지 실패 재현 및 수정

실제 Engine 2.5.1 서버와 공개 모델 연결 경로에 로컬 OpenAI 호환 시험 응답 서버를 연결했다. 0.8.0 ZIP과 0.8.1 ZIP에 동일한 활동·응답을 제공했다. 외부 유료 모델은 호출하지 않았다.

| 조건 | 0.8.0 재현 | 0.8.1 검증 결과 |
| --- | --- | --- |
| 정상 JSON을 전체 Markdown 코드블록으로 반환 | HTTP 502 `generation_failed` | 추가 모델 호출 없이 해석·저장 성공 |
| 우편 200개에 해당 활동의 시스템 결과 우편 포함 | 모델 호출 전 HTTP 400 `invalid_payload` | 중복 시스템 우편 한 칸을 AI 편지로 대체, 총 200개 유지 |
| 출력 예산 | 실제 요청 `max_tokens: 600` | 실제 요청 `max_tokens: 2048`; 더 작은 연결 한도는 존중 |
| 출력 잘림 | 일반 실패 안내 | `details.stage: output_limit` 및 설정/재시도 안내, 원본 활동 우편 보존 |
| 이미 저장된 편지 다시 요청 | 비교 대상 | 저장 결과 재사용, 모델 호출 0회 |

코드블록은 전체 응답을 감싼 경우만 허용한다. 불필요한 필드·잘못된 형식은 엄격히 거부한다. 출력 잘림·빈 응답·요청 실패·형식 오류를 구분하고 원문 응답이나 연결 비밀을 노출하지 않는다. 입력 문맥이 부족하면 공방 프로필을 임의로 잘라 생성하지 않는다. 자동 복구용 추가 유료 호출은 없다.

우편 교체는 활동의 `mailId`, 우편의 `eventId`, 본문과 불변 활동 요약의 일치까지 확인한다. 원문이 다른 우편과 나머지 199개 우편은 그대로 두며, 활동 요약과 기존 보관함 선택을 유지한다. 200개 우편/100개 완료 활동 제한 및 저장 스키마는 변경하지 않았다.

실패는 해당 공방·활동에 표시하고 다른 화면의 알림을 지우지 않는다. 실패를 알고 있는 편지를 열기만 해서는 모델을 다시 호출하지 않는다. 플레이어가 재시도하며, 요청 중 창을 닫거나 다른 편지를 선택하면 결과를 강제로 열거나 읽음 처리하지 않는다. 기존 활동 결과 링크는 새 AI 편지로 이어진다.

## 검증 범위

- 회귀 22개 스위트 통과: 코드블록, 모델 예산, 빈/잘린/잘못된 응답, 요청 실패, 중복 호출, 우편 가득 참, 보관 상태와 원문 보존 포함.
- Engine 2.5.1 타입 기반 엄격 검사: 서버 87개·클라이언트 71개 파일 통과. 전체 포맷·린트 통과.
- 레이아웃 473건(14개 경로·94개 상태, 모바일 및 데스크톱) 통과. 중앙 팝업, 목표 버튼과 수동 설정 입구, 실패/대기/보관 우편 상태를 포함한다.
- 브라우저 조작: 생산 수량 999 직접 입력 및 한 번 적용, 편지 실패/명시적 재시도/닫기, 프로필 이름 편집, 우편 보관, 무료 초대권 수령 통과.
- 최종 ZIP을 격리된 데이터 폴더에 설치해 실제 Engine + Vite 전체 프레임에서 편지 출력 한도 실패 → 코드블록 응답 재시도 → 읽기 → 재열기 시 호출 없음, 생산 목표 입력·실제 작업 현황 전환, 주민 팝업 중앙 정렬, 무료 초대권 수령 후 버튼 위치 유지를 검증했다.
- 실제 엔진 백업/복원 및 정상 종료 후 재시작에서 생성 편지·보관 상태·활동 요약·전체 우편이 그대로 유지되는 것을 확인했다.
- 카탈로그 v2/v3 및 레거시의 버전·릴리스 노트·ZIP SHA-256/바이트·manifest 파일 해시 검증 통과. 생성 번들은 빌드 스크립트로만 생성한다.

Engine 체크아웃: `/workspace/ME-personal`, 버전 2.5.1, 검증 HEAD `b8bf28382b740cac77f310df442f98c493166f43`. manifest의 호환 기준 `7f341f9186db8e08f21d63cc47ec458deff250d5`는 유지한다.

## 미검증 및 다음 확인 지점

사용자가 실제 연결한 외부 모델과 그 실패 응답은 제공되지 않아 같은 원인이라고 단정하지 않는다. 로컬 시험 모델은 엔진 어댑터·설정·HTTP·저장·UI 경로를 검증하지만 외부 서비스 장애나 모델별 출력 품질까지 보증하지 않는다. Android 실기기/PWA 설치 검증은 하지 않았다. ZIP은 저장소의 설치 fixture로 엔진에 배치했으며 원격 카탈로그 UI 다운로드 절차는 수행하지 않았다. main 병합과 원격 main ZIP 공개 여부는 PR 병합 후 별도로 확인해야 한다.
