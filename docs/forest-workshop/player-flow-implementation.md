## 실제 엔진에서 추가 발견하고 고친 저장 문제

세계 전체 revision이 달라졌다는 이유만으로 이름/배치 저장이 실패하면 생산 갱신 중 편집을 마칠 수 없었다. 이름은 편집 시작 이름, 배치는 편집 시작 지면/게시판 값과 비교하는 전용 명령으로 변경했다. 무관한 재고·시간 갱신은 허용하고 같은 대상을 다른 곳에서 바꿨으면 충돌을 거부한다. 이름 입력 초안은 화면 갱신 중에도 유지한다.

## 저장 이전과 보존

- 스키마 12 → 13에서 지정 횟수의 미시작 요청은 제거한다. 이미 투입된 작업의 입력·출력·남은 시간은 보존한다.
- 기존 목표·우선순위·주민·그림·이야기·기억·재화는 보존한다. 제작법 켜짐은 이번 요청대로 한 번 초기화한다.
- 게시판 위치는 세계 설정에 보관되어 기존 전체 세계 백업에 포함된다. 이전 패키지는 스키마 13을 읽을 수 없으므로 다운그레이드는 이전 백업을 사용해야 한다.
- 권한 범위와 Engine 호스트 계약은 확장하지 않았다. 이름은 원본 카드에 쓰지 않고, 초대권은 외부 결제 API를 호출하지 않는다.

### 실제 Engine 통합 확인

ME-personal 2.5.1 로컬 체크아웃 `b8bf28382b740cac77f310df442f98c493166f43`에서 실행했다. 선언된 빌드 기준은 기존 `7f341f9186db8e08f21d63cc47ec458deff250d5`를 유지했다.

생성한 ZIP을 검증 후 `/tmp/forest-player-engine`의 격리된 패키지 폴더에 fixture 방식으로 설치했다. 실제 엔진 서버와 Vite 클라이언트를 실행하고 390×844 Chromium에서 서재 배너로 진입했다. 신규 세계와 테스트 캐릭터 3명·페어 2개를 사용했다.

확인한 실제 조작: 첫 설정 화면, 무료 초대권 1,000장 2회 리필, 주민 상세/프로필 열기, 공방 이름 저장 후 팝업 유지, × 닫기, 게시판 위치 저장과 편집 종료, 생산 설정/우선순위 표시 및 제작 트리 명령. 원본 캐릭터 이름은 변경되지 않았다. 정상 종료·재시작 뒤 게시판 위치·공방 이름·초대권이 유지되는 것을 다시 비교했다.

통합 화면 캡처와 결과는 해당 실행 환경의 `/tmp/fw-player-engine-onboarding.png`, `/tmp/fw-player-engine-shop.png`, `/tmp/fw-player-engine-production.png`, `/tmp/fw-player-engine-ui-results.json`에 남겼다. 패키지 원본 소스의 전체 프레임 캡처는 `/tmp/forest-player-flow-layout/`에 있다. 이 임시 증거 파일은 작업 환경 정리 시 사라질 수 있다.

실제 Android 하드웨어, 정상 다운로드 카탈로그의 설치/업데이트 UI, 제거·오프라인 재시작, 실제 외부 AI 모델의 B페어 오류와 음질 청감은 검증하지 않았다. 브라우저/ZIP fixture 확인을 이 항목들의 검증으로 표현하지 않는다. 저장소 Issues 기능은 비활성화되어 PR에 범위를 기록했다.
